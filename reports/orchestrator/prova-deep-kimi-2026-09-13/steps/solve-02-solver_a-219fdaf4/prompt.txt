import numpy as np

def split_cells(cells, seed=42):
    """cells: lista di record con cell_id e cell_line."""
    rng = np.random.default_rng(seed)
    indices = rng.permutation(len(cells))
    cut = int(0.8 * len(indices))
    train = [cells[i] for i in indices[:cut]]
    test = [cells[i] for i in indices[cut:]]
    return train, test

def summarize(loss_a, loss_b):
    """Ogni posizione rappresenta lo stesso caso nei due array."""
    a = np.asarray(loss_a, dtype=float)
    b = np.asarray(loss_b, dtype=float)
    a = a[np.isfinite(a)]
    b = b[np.isfinite(b)]
    delta = a.mean() - b.mean()
    winner = "A" if delta > 0 else "B"
    return {"delta": float(delta), "winner": winner}

Revisione critica.

1) Errori di implementazione.
E1. summarize filtra a e b indipendentemente con np.isfinite, mentre la docstring dice che le posizioni corrispondono allo stesso caso. Correzione minima: mask = np.isfinite(a) & np.isfinite(b); a = a[mask]; b = b[mask].
E2. summarize inverte il vincitore. Con delta = media_a - media_b, se delta > 0 allora A ha loss media maggiore e B è migliore. Il codice sceglie A se delta > 0. Correzione: A vince se delta < 0, B vince se delta > 0, altrimenti pareggio.
E3. summarize non gestisce il pareggio: delta == 0 restituisce B. Correzione: restituire winner='tie' o equivalente.
E4. split_cells permuta record, non cell_line. Se più record condividono cell_line, non garantisce separazione per linea. Correzione minima, se l'obiettivo è linee mai viste: splittare le cell_line uniche e assegnare tutti i record di una linea allo stesso lato.

2) Problemi metodologici.
M1. Split casuale a livello record non garantisce generalizzazione a linee mai viste. Controesempio: due record con stessa cell_line='L1', len=2, cut=1; qualunque permutazione mette un record L1 in train e uno in test.
M2. Media per record non è necessariamente la metrica giusta se l'unità è la linea cellulare. Controesempio: 99 record di L1 con loss 0 e 1 record di L2 con loss 1; la media per record è circa 0.01, la media per linea è 0.5.
M3. Il missing non è necessariamente casuale. Nei dati, A manca su c2 e B manca su c3; anche con accoppiamento corretto si escludono casi diversi e il sottoinsieme comune può non essere rappresentativo.
M4. Un solo split e n=2 casi comuni non permettono stime di incertezza o conclusioni stabili.

3) Correzione minima e decisioni dell'operatore.
Correzione minima lato codice: usare maschera congiunta in summarize, correggere il segno del vincitore, gestire pareggio e n=0. Lato split: se l'obiettivo dichiarato è linee mai viste, raggruppare per cell_line. Decisioni dell'operatore: se ogni cell_line ha un solo record o più record; se il test deve contenere intere linee; come trattare i missing; se usare media per record, per linea o mediana; se ripetere lo split o usare GroupKFold/leave-cell-line-out; quale frazione e seed usare.

4) Confronto a mano sui casi validi per entrambi.
Casi comuni validi: c1 e c4. c2 manca in A, c3 manca in B.
A: 0.2, 0.4 -> somma 0.6, media 0.300.
B: 0.3, 0.5 -> somma 0.8, media 0.400.

5) Cosa non si può concludere.
Non si può concludere che A generalizzi meglio a linee cellulari mai viste. Non si può concludere superiorità statistica, né stabilità su altre linee. Non si può valutare leakage senza sapere quante cell_line e quanti record per cell_line esistono. Non si può stimare incertezza da n=2.
